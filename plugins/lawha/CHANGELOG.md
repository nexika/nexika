# Changelog

All notable changes to lawha are documented here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and versions follow [Semantic Versioning](https://semver.org/).

## [0.1.0] - 2026-10-08

### Added
- lawha check renders the widths, themes and directions in parallel browser contexts (one per CPU, up to 8; --concurrency to change it): the full matrix is about 5 times faster, with the same report. bench/speed.mjs measures it. (#106)
- lawha check walks the page with Tab like a keyboard user: a focus order that goes against the visual reading order (a positive tabindex, row-reverse, CSS order) is a should-fix, and a stop with no visible focus (outline: none with nothing in its place) is a must-fix. (#107)
- `lawha check` can check pages behind login (`--storage-state`, `--cookie`, `--header`, sent to the page's own origin only) and wait for apps that draw after the load event (`--wait-for <selector>`, `--network-idle`, `--settle <ms>`). (#54)
- A public benchmark (benchmarks/): the same tasks, starter app and scoring script for lawha and the leading tools. Brief to page: lawha and Anthropic's frontend-design both did the whole brief with no must-fix problems; blind judges picked lawha's page 6 times out of 6. Figma to code (lawha, Figma MCP, Builder.io) is set up for the account-based runs. lawha check now scrolls through the page before measuring, so sections that appear on scroll are checked and photographed, and lawha ab shows both pages in full instead of cutting them at 4000px. Found by the benchmark's Figma run and fixed: - **Photos:** layers that share a name ("Rectangle 6") no longer overwrite each other's photos. - **Colour styles:** they keep their opacity in theme.css. - **Mixed text sizes:** the spec now lists the base size when a longer run sets the main style. - **Icons:** icons that only exist in the phone or tablet frame are exported too. - **Text over images:** contrast is measured against the real background behind the letters, by hiding the text for one screenshot, instead of guessing from pixels that include the letters' soft edges. (#21)
- /lawha:direct gives a project a design when you cannot picture one: three complete directions, checked for contrast, the known AI looks and sameness, rendered at phone and desktop, chosen by looking, applied as Tailwind and shadcn tokens. /lawha:inspire learns a design from sites you like (fonts with licences and free look-alikes, palette, scale, spacing, motion, libraries such as Three.js). /lawha:elevate improves a working page and keeps a change only when a blind judge prefers it side by side (lawha ab), learning your taste from your picks. Three.js recipes for React Three Fiber respect reduced motion; lawha check now fails 3D scenes that keep moving under "reduce motion" and text that is hard to read over images, video or 3D, names what moved when the layout shifts, and ignores screen-reader-only text. (#20)
- /lawha:figma reads the prototype's motion: each interaction's trigger, action and transition (Smart Animate, dissolve, move in, slide, push) become the exact Motion transition (Figma curves as cubic Béziers, Figma springs and custom springs as springs), with slide directions written logically so they mirror in Arabic, the recipe that builds it, and what changes between a layer and its variant. No extra Figma calls: interactions come with the frames. (#21)
- /lawha:figma builds a Figma design in code: the frames are read in a few batched, cached calls with the call budget shown, merged into one mobile-first spec (Auto Layout as flex, styles as tokens, real line heights, vertical trim, style overrides, typed line breaks, photos and SVG icons, design-file habits read as intent), built in your stack and checked against each frame; lawha check --against now reports how much the page looks like the design with content aligned, besides position for position, and where heights drift. (#19)
- lawha checks every page at six screen widths, light and dark, LTR and RTL and with reduced motion: sideways scrolling, clipped and overlapping text, tap targets, accessibility (axe), layout shift, motion and left/right CSS that breaks Arabic, with an eye that measures alignment, spacing rhythm, type scale and colour, a pixel diff against design exports, a report with every screen, fixes proposed from the screenshots through /lawha:check --fix, and /lawha:system to index Tailwind tokens, shadcn components, your components with their props and TanStack routes. (#18)
- Motion recipes for React with Motion: entrances in reading order, count-up, page cross-fade, a shared-layout tab mark, press feedback, a sheet on the native dialog, toasts, skeleton to content without a jump, and six signature movements. They are timed by the chosen direction (the theme now writes --lawha-motion and its durations), mirror in Arabic and respect reduced motion. lawha check now warns about motion that never stops (WCAG 2.2.2) and interface motion slower than a second, recording every animation from the first frame. (#21)
- lawha check compares every icon between the English and Arabic renders. Icons that show direction (arrows, chevrons, send, reply, undo and redo, log-out, alignment, lists, text arrows such as →) must point the other way in Arabic, and media controls, clocks, ticks and logos must not be mirrored. Names come from lucide, tabler, Font Awesome, Bootstrap Icons, Material ligatures, sprites and file names. An app that swaps the icon itself in RTL counts as mirrored, and Tailwind 4's rotate and scale properties are read as well as transform. (#21)

### Fixed
- `lawha check` now exits 1 when the verdict is fail, so CI and itqan gates stop on a failing page; `--no-fail-exit` keeps exit 0 for callers that read the JSON. (#27)
- A page that redirects elsewhere (usually to a login page) now fails the check with `page.redirected` instead of recording the login page as the page asked for. (#28)
- Hooks exit at once inside a Nexika background model call (NEXIKA_BACKGROUND=1), so other plugins' paid `claude -p` jobs no longer start this plugin's hooks. (#45)
- RTL checks now run at every width and read `style` attributes, so a phone-only menu or an inline `margin-left` is caught (#55)
- motion driven by script (requestAnimationFrame, timers) that ignores "reduce motion" is now found (#55)
- a link inside a sentence no longer fails the tap-target check (the WCAG 2.5.8 inline exception) (#55)
- A broken or half-written module no longer takes down every lawha command: each command loads only what it uses. (#82)
- A layout shift is one problem however many widths and elements it shows on, and a shift is measured over three loads and reported as the median, so one unlucky load no longer fails a page (#83)
- `lawha index` reads Next.js routes (app and pages router), Vue components with their props and drift, and Tailwind 3's `tailwind.config.js` tokens (#83)
