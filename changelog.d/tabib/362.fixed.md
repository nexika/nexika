A test that runs out of time in only one job of a matrix is now called likely flaky (low confidence, re-run to tell), not 'fails only on <version>'. A pytest test that fails before its body runs (inside unittest's case.py) no longer gets a library frame's line paired with the test file, and a coverage list the tool cut short ('...22-132,134-144') gives the first range shown whole, not the end of the cut one.
